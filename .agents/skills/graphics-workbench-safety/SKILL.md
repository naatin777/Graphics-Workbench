# 安全性レビュー

入力の選択から、ユーザーに見える最終出力が確定するまでの処理を確認する。

## 手順

1. 現在の差分を確認する。
2. 変更された処理の入力から出力までを追う。
3. 成功、失敗、キャンセルの各経路を確認する。
4. 関連する既存テストを確認する。
5. 外部変更との競合とcleanup失敗を注入できるテスト境界を確認する。

## 確認項目

- ワークスペースのパス検証を迂回していない。
- 適用可能な場合は既存のステージング経路を使用している。
- Safe Modeと上書き防止が維持されている。
- 失敗時に元ファイルを置換または削除しない。
- rollback対象はユーザーファイルの変更開始直前に追加される。
- rollback / Undoの復元前に、現在状態が自処理の期待する中間状態か再検証される。外部変更の疑いがある場合は上書き・削除せず、recovery copyを保持する。
- commit時のdigestをUndo記録へ引き継ぎ、commit後の外部変更を変換結果として記録しない。
- 通常の一時artifactは成功、失敗、キャンセル後に削除する。Undo backup、rollback recovery、cleanup失敗artifactは必要な期間だけ保持する。
- cleanup失敗時は追跡情報をmanifest等へ残し、次回cleanupで再試行できる。
- キャンセル要求後に新しい最終出力を確定しない。
- ロールバックとUndoに必要な情報が維持されている。
- 存在しない、空、形式不正な生成出力を成功扱いしない。

Node.js標準APIで完全に排除できないTOCTOUと現在の緩和策は、`docs/specs/internal/file-operation-security.md`の「競合」を正本とする。実装が提供していない厳密なCASや排他保証を前提にしない。

## 範囲

変更された処理だけを確認する。
関係のないリファクタリングは提案しない。

## 報告形式

- 修正必須
- 修正推奨
- 確認済み
- 未確認
